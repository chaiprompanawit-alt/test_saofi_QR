# แผนงาน: ส่งงานถึงช่าง → ช่างปิดงานพร้อมรูป → เก็บติดตาม 7 วัน

> สถานะ: **แผน ยังไม่ได้เขียนโค้ด** (18 ก.ย. 2569) · ต่อยอดจากเวอร์ชัน Vercel + Supabase ใน `web/`
> เป้าหมาย: งานทุกใบมี "หลักฐานปิดงาน" (รูป + ใคร + เมื่อไร + ที่ไหน) และยังตามผลได้อีก 7 วันหลังปิด

---

## 1. ภาพรวมการไหลของงาน (เชิงธุรกิจ)

```
ชาวบ้านสแกน QR ──► [แจ้งใหม่] ──► แอดมิน/หัวหน้าช่าง "มอบหมาย" หรือช่าง "รับงานเอง"
                                        │
                                   [รับเรื่องแล้ว] ── ช่างกด 🧭 นำทาง ไปถึงเสา
                                        │
                                   [กำลังดำเนินการ] ── ซ่อม
                                        │
                                   📸 ปิดงาน: ถ่ายรูปหลังซ่อม (บังคับ) + บันทึกสาเหตุ/อะไหล่
                                        │   ระบบเก็บ: รูป · ชื่อช่าง · เวลา · GPS ตอนถ่าย
                                   [เสร็จสิ้น]
                                        │
                              ⏳ ระยะติดตามผล 7 วัน
                              · งานยังโชว์ในหน้าช่าง แท็บ "ปิดแล้ว (7 วัน)"
                              · ถ้าเสาเดิมถูกแจ้งซ้ำใน 7 วัน → เปิดงานใหม่ ติดป้าย "🔁 เสียซ้ำหลังซ่อม"
                                และผูกกับช่างคนเดิมอัตโนมัติ
                                        │
                              พ้น 7 วัน → เข้าคลัง (แอดมิน/รายงานยังเห็นครบ ช่างไม่เห็นในหน้างานประจำ)
```

**หน้าที่ช่าง (SOP สั้น ๆ ติดไว้ในหน้าช่างได้เลย)**
1. เปิดแอป → ดู "งานของฉัน" → กด 🧭 นำทาง
2. ถึงเสา → กด "เริ่มงาน" (สถานะเป็น กำลังดำเนินการ)
3. ซ่อมเสร็จ → กด "📸 ปิดงาน" → ถ่ายรูปโคมที่ติดแล้ว (ถ่ายให้เห็นเลขเสา/สติกเกอร์ QR ในรูปด้วย) → เลือกสาเหตุ → บันทึก
4. ระบบล็อกงานเป็น เสร็จสิ้น — แก้ไขได้ภายใน 7 วันโดยช่างคนเดิม/แอดมินเท่านั้น

## 2. สิ่งที่ต้องเพิ่มในระบบ (เชิงเทคนิค)

### 2.1 ฐานข้อมูล (Supabase) — `supabase/schema.sql`
| ตาราง | เพิ่ม | ใช้ทำอะไร |
|---|---|---|
| `reports` | `assigned_at`, `started_at`, `done_by` (username), `done_lat`, `done_lng`, `cause` (สาเหตุ), `parts` (อะไหล่), `repeat_of` (report_id งานเดิมถ้าเสียซ้ำ) | ไทม์ไลน์งาน + หลักฐานว่าใครปิด ที่ไหน |
| `report_photos` (ใหม่) | `id`, `report_id`, `kind` (`before`/`after`), `path` (ใน Storage), `taken_at`, `taken_by`, `lat`, `lng` | รูปหลายใบต่อ 1 งาน |
| Storage bucket `repair-photos` | **private** (เปิดดูผ่าน signed URL อายุ 1 ชม.) | รูปมีเบอร์/หน้าบ้านชาวบ้านได้ → ไม่เปิดสาธารณะ (PDPA) |

### 2.2 API (Vercel Functions)
| ไฟล์ | ทำอะไร |
|---|---|
| `api/upload.js` (ใหม่) | ช่างล็อกอินขอ **signed upload URL** → อัปโหลดรูปตรงเข้า Supabase Storage (ไม่ผ่านเซิร์ฟเวอร์ ไม่ติดลิมิต 4.5 MB ของ Vercel) |
| `api/update.js` (แก้) | ถ้าเปลี่ยนสถานะเป็น **เสร็จสิ้น** ต้องมีรูป `after` ≥ 1 ใบ ไม่งั้นปฏิเสธ (บังคับฝั่งเซิร์ฟเวอร์ ไม่ใช่แค่หน้าเว็บ) · บันทึก `done_at/done_by/done_lat/done_lng` · เพิ่มปุ่ม "รับงาน" (assigned_to = ตัวเอง) และ "เริ่มงาน" (started_at) |
| `api/report.js` (แก้) | ตอนรับแจ้งใหม่ เช็คว่าเสานี้มีงาน **เสร็จสิ้น ภายใน 7 วัน** ไหม → ถ้ามี ตั้ง `repeat_of` + `assigned_to` = ช่างคนเดิม + อีเมลแจ้ง |
| `api/reports.js` (แก้) | หน้าช่างส่งงานเปิด + งานเสร็จสิ้นที่ `done_at` ≥ 7 วันย้อนหลัง · แอดมินเห็นทั้งหมดเหมือนเดิม |
| `api/photo.js` (ใหม่) | คืน signed URL สำหรับดูรูป (เช็คล็อกอิน) |

### 2.3 หน้าช่าง `tech.html` + `common.js`
- ปุ่ม **"รับงาน"** (งานที่ยังไม่มีผู้รับผิดชอบ) และ **"เริ่มงาน"**
- ปุ่ม **"📸 ปิดงาน"** เปิดกล่อง:
  - `<input type="file" accept="image/*" capture="environment">` → เปิดกล้องหลังทันทีบนมือถือ (คอม/แท็บเล็ตเลือกไฟล์ได้)
  - ย่อรูปในเครื่องก่อนส่ง (Canvas → ≤ 1600 px, JPEG 0.8 ≈ 200–400 KB) ประหยัดเน็ต/พื้นที่
  - ขอ GPS ตอนถ่าย (ยืนยันว่าอยู่ที่เสา — ถ้าห่างจากพิกัดเสา > 300 ม. เตือน แต่ไม่บล็อก)
  - ช่องเลือกสาเหตุ (หลอด/บัลลาสต์/โฟโต้สวิตช์/สายขาด/เบรกเกอร์/อื่น ๆ) + อะไหล่ + หมายเหตุ
- แท็บ/ฟิลเตอร์ใหม่ **"ปิดแล้ว (7 วัน)"** และป้าย **"🔁 เสียซ้ำหลังซ่อม"** สีม่วงในการ์ด
- การ์ดงานโชว์รูปย่อ แตะขยาย
- **ออฟไลน์**: ถ้าส่งรูปไม่สำเร็จ เก็บใน IndexedDB แล้วส่งใหม่เมื่อมีเน็ต (ต่อยอดจาก Service Worker ที่ทำไว้แล้ว — เฟส 3)

### 2.4 หน้าแอดมิน / รายงาน
- รายงานรายสัปดาห์/เดือน เพิ่ม KPI **"เสียซ้ำใน 7 วัน"** (คุณภาพงานซ่อม) และ **"เวลาเฉลี่ย รับงาน→ปิดงาน"** ต่อช่าง
- ตารางงานมีคอลัมน์รูป (พิมพ์ PDF ติดรูปย่อ 1 ใบ)
- ตารางเสาไฟ: ประวัติซ่อม + สาเหตุที่พบบ่อยต่อต้น (เสาที่ซ่อมบ่อย = ควรเปลี่ยนทั้งชุด)

## 3. กฎ "7 วันหลังปิดงาน" (ตีความและทางเลือก)

ตีความที่ใช้ในแผนนี้: **7 วัน = ระยะติดตามผล/รับประกันงาน** — งานยังอยู่กับช่าง แก้ไขได้ แจ้งซ้ำแล้วกลับมาหาคนเดิม พ้นแล้วจึงถือว่าปิดสนิท ข้อมูลและรูปยัง**เก็บถาวร**ไว้ในระบบเพื่อรายงาน/ตรวจสอบ

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **A. เก็บถาวร (แนะนำ)** — 7 วันเป็นแค่ช่วงติดตาม | มีหลักฐานย้อนหลังตอนถูกตรวจ/ร้องเรียน · วิเคราะห์เสาซ่อมบ่อยได้ | ใช้พื้นที่ (ประเมิน: 60 งาน/เดือน × 2 รูป × 300 KB ≈ 36 MB/เดือน → Supabase ฟรี 1 GB อยู่ได้ ~2 ปี, ถ้าเต็มย้ายรูปเก่า > 1 ปีออกด้วย cron) |
| B. ลบรูปหลัง 7 วัน เหลือแต่ข้อความ | พื้นที่แทบไม่โต | ไม่มีหลักฐานเมื่อมีปัญหาหลัง 7 วัน · รายงานประจำเดือนไม่มีรูป |

> ✅ **ตัดสินใจแล้ว (18 ก.ย. 2569): ใช้แบบ A เก็บถาวร**

## 4. ลำดับการทำ (ประเมินเวลา)

| เฟส | งาน | เวลา |
|---|---|---|

| 2 | รับงาน/เริ่มงาน · แท็บ "ปิดแล้ว 7 วัน" · ตรวจเสียซ้ำใน 7 วัน + แจ้งช่างคนเดิม | 1 วัน |

2. รูป **ก่อนซ่อม** บังคับด้วยไหม (แผนนี้ = ไม่บังคับ บังคับเฉพาะ **หลังซ่อม**)
3. ~~เก็บรูปถาวร (A) หรือลบหลัง 7 วัน (B)~~ → **A เก็บถาวร** (ตัดสินใจแล้ว)
